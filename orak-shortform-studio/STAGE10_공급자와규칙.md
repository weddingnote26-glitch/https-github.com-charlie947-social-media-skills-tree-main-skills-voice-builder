## 4. 공급자 — **모델 이름을 코드에 박아두지 않았습니다**

이번 지시서가 「모델명을 하드코딩하지 말고 설정값으로」 라고 했고,
원래 지시서 §0-2 도 「모델명을 추측하지 마세요」 라고 했습니다. 그래서 이렇게 합니다.

```
[연결 확인] → 계정에 물어봄 → **실제로 쓸 수 있는 목록** → 담당자가 고름
→ settings 에 저장 → 그 값으로 부름

안 골랐으면 → 부르지 않고 멈춤 (돈도 안 나가고 엉뚱한 답도 안 옴)
```

코드 안에 있는 모델 이름은 **0개**입니다. 시험으로 못 박았습니다.

### 4-1. 대본 — OpenAI `app/providers/llm_openai.py`

## 5. 기본 제작 필수 규칙

### 어디에 있나

**설정 화면 안**에 넣었습니다. 지시서가 「설정 화면 또는 별도 메뉴에」 라고 했고,
메뉴를 늘리면 Stage 2 에서 못 박은 「메뉴 4개」 가 깨지기 때문입니다.
따로 떼고 싶으면 `RulesPanel` 을 새 화면에 그대로 옮기면 됩니다.

### 저장 방식

`rulesets` 표 — **열쇠와 다른 표**입니다.

```sql
rulesets(id, section, body, scopes, enabled, sort_order, is_builtin, updated_at)
```

`scopes` 는 `script,image,caption` 처럼 쉼표로 둡니다. 모르는 이름이 섞여 있어도
버리고 넘어갑니다 — 저장된 글자가 낡아도 앱이 멈추면 안 됩니다.

본문은 `Database._clean()` 을 거칩니다. **담당자가 실수로 열쇠가 든 문장을
붙여넣어도 평문으로 남지 않습니다.** (§0-3 · MVP 판정 18번)

### 담당자가 할 수 있는 것

| 지시서 요구 | 됨 |
|---|---|
| 규칙 입력/수정 가능 | ✅ |
| 규칙 저장 가능 | ✅ |
| 앱 재실행 후에도 유지 | ✅ 시험 `test_껐다_켜도_남아_있다` |
| 제작 실행 시 자동 참조 | ✅ |
| 규칙 켜기/끄기 | ✅ 줄마다 체크박스 |
| 어떤 작업에 반영할지 선택 | ✅ 주제찾기·기획·대본·이미지·게시글·성과 |
| 기본 템플릿 불러오기 | ✅ **고쳐 둔 문장은 안 덮습니다** |
| 규칙 미리보기 | ✅ 실제 가는 글과 **같은 글** |
| 이번 작업에서만 임시 규칙 | ✅ 저장되지 않습니다 |
| 제작 시 자동 반영 여부 | ✅ 맨 위 체크박스 |

기본 템플릿은 지시서의 8항목 **36줄** 그대로 들어 있습니다.

### 실제로 프롬프트에 섞입니다

메모장이 아닙니다. 이렇게 조립됩니다.

```
[이번 콘텐츠]
- 주제: 신림동 손칼국수
- 올릴 곳: 인스타그램 릴스
- 길이: 30초
- 보는 사람: 50~70대
- 지역: 신림동

[대본을 쓸 때 지킬 것]
- 주제 발굴
  · 담당자가 입력한 지역·업종·주제와 관련 있는 내용을 먼저 쓴다.
- 릴스 / 쇼츠 대본
  · 처음 3초에 사람을 붙잡는 문구를 넣는다.
  …
```

이 글이 `build_user_prompt()` 를 거쳐 **진짜로 공급자까지 갑니다.**
시험 `test_규칙이_대본_요청에_실려_간다` 가 보낸 몸통을 열어서 확인합니다.

**작업마다 다른 규칙이 갑니다.** 「해시태그를 넣는다」 는 게시글에만 가고
대본에는 안 갑니다. 이것도 시험이 양쪽으로 확인합니다.

시스템 프롬프트가 아니라 **사용자 쪽 요청문에** 붙입니다 —
시스템 프롬프트에는 캐시가 걸려 있어서, 매번 바뀌는 글을 넣으면 값이 올라갑니다 (§6).

## 6. 주제 발굴 · 경쟁 분석 — **자동 수집은 안 만들었습니다**

지시서가 「인스타그램 사례 분석 · 유튜브 사례 분석」 을 말합니다. 그런데
같은 지시서 §0-4 가 이렇게 못 박았습니다.

> **웹 자동 수집(스크래핑) 코드를 만들지 마세요.**
> 참고 URL은 **저장만** 하세요.
> 로그인 우회, 비공개 페이지 접근, 보안 우회, headless 브라우저 자동화 — 전부 금지입니다.

당근에서 이미 같은 문제를 겪었습니다. 그래서 **구조·저장·화면까지만** 만들었습니다 —
이번 지시서도 「이번 단계에서는 실제 대규모 수집/크롤링보다 먼저 구조 / 데이터 저장 /
UI / 서비스 연결을 우선한다」 고 했으니 어긋나지 않습니다.

```
TopicDiscoveryService          주제를 적어 두고 꺼내 씀 · fetch_hook 자리 비워 둠
CompetitorAnalysisService      사례를 적어 둠 (인스타·유튜브·블로그)
PerformanceAnalysisService     담당자가 넣은 수치로 고칠 거리를 말해 줌
```

**주소는 프롬프트로 넘기지 않습니다.** 담당자가 적은 메모만 넘깁니다 —
주소를 넘기면 AI 가 그걸 열어보려 할 수 있고, 그것도 §0-4 위반입니다.
`research.py` 에 `requests.get`·`urlopen`·`selenium`·`playwright` 가
없는 것을 시험이 확인합니다.

나중에 **공식 API**(예: YouTube Data API) 를 붙일 자리는 `fetch_hook` 으로 비워 뒀습니다.

## 7. 한 단계가 실패해도 앱이 안 죽습니다

```
담당자 입력 → 주제 발굴 → 경쟁 콘텐츠 분석 → 콘텐츠 기획 → 대본 작성
→ 이미지 생성 → 음성 생성 → 영상 생성 → 게시글/캡션 생성 → 결과 저장
```

`Production.run()` 안에서 **어떤 예외도 밖으로 나가지 않습니다.**

```
대본 만들기: 완료
이미지 만들기: 실패 — 이미지 만들기에 실패했습니다. 인터넷 연결과 설정을 확인해 주세요.
목소리 만들기: 완료          ← 이미지가 실패해도 계속 갑니다
```

이미 끝난 단계를 다시 부르지 않습니다. **영상은 한 번에 몇백 원씩 나갑니다.**
음성에서 실패했다고 처음부터 다시 하면 이미 낸 돈을 또 냅니다.

「다시 해도 소용없는 것」(모델을 안 골랐다 등)은 [다시 시도] 를 띄우지 않습니다.

| 대본 규칙을 게시글에도 넣음 | ✅ 양쪽으로 확인 |

## 10. 지운 것 · 안 지운 것

**아무것도 지우지 않았습니다.**

- 표 5개 그대로 · 쓰던 db 파일을 열어도 자료가 남는 것까지 시험합니다
- Claude 대본 공급자 그대로 · Gemini 열쇠 칸 그대로
- Stage 2 화면·Stage 6b·8·9 그대로

DB 에서 `DELETE` 를 쓰는 곳은 **규칙 한 줄을 지울 때뿐**입니다.
그건 담당자가 자기가 적은 것을 되돌리는 일이지 결과물을 지우는 게 아닙니다.
시험이 `DELETE FROM` 대상이 `rulesets` 하나뿐인지 확인하고,
실제로 규칙을 지운 뒤 프로젝트·장면이 남아 있는지도 확인합니다.
