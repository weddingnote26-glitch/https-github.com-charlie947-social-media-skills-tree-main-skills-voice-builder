## 2. 화면 규칙을 위젯 안에 넣었습니다

지시서 §9 의 규칙을 화면마다 다시 떠올리지 않아도 되게, 조각 안에 넣어두었습니다.

| 규칙 (§9 · §11) | 어디에 들어갔나 |
|---|---|
| AI 버튼 중복 클릭 금지 | `BusyButton` — 누르는 **즉시 스스로 잠깁니다.** 부르는 쪽이 깜빡해도 잠긴 채로 남아 돈이 두 번 나가지 않습니다 |
| 개발자 로그 금지 | `NoticeBox` · `ErrorBox` — 한국어 평문만 받습니다 |
| 오류에는 [다시 시도] | `ErrorBox` 에 버튼이 **처음부터 붙어 있습니다** |
| 비용을 항상 표시 | `CostBar` — 창 맨 아래, 메뉴를 바꿔도 사라지지 않습니다 |
| 80% 경고 · 100% 차단 | `CostBar.set_usage()` 가 색과 문구를 바꿉니다 |
| 진행 상황을 한글로 | `StepTrail` — 대본→이미지→영상→음성→자막→합성 |

## 3. 시험 16개 — 전부 통과

화면이 없는 이 컴퓨터에서 Qt 를 offscreen 으로 띄워 **실제로 눌러봤습니다.**

```
통과   메뉴는_정확히_네개다
통과   메뉴를_누르면_화면이_넘어간다          ← Stage 2 완료 기준
통과   입력에서_완료까지_눌러서_갈_수_있다
통과   AI버튼은_두번_눌러도_한번만_동작한다
통과   참고URL_안내가_화면에_붙어있다
통과   참고URL을_추가할_수_있다
통과   대가성을_켜면_안내가_뜬다
통과   비용표시줄이_항상_보인다
통과   한도를_넘으면_문구가_바뀐다
통과   입력칸_이름이_잘리지_않는다
통과   화면에_개발자_말이_없다
통과   새영상_모든_단계에도_개발자_말이_없다
통과   캐릭터화면이_없는_기준이미지를_알려준다
통과   캐릭터화면이_안적은_색을_알려준다
통과   설정의_열쇠칸은_아직_잠겨있다
통과   설정에_배경음악_저작권_안내가_있다
```

### 시험 두 개는 좀 특별합니다

**「화면에 개발자 말이 없다」** — 모든 화면의 글자를 훑어서 `Traceback` · `HTTP` ·
`1303` 같은 공급자 오류코드 · JSON 원문이 섞이지 않았는지 봅니다.
§9 를 사람 눈이 아니라 시험이 지키게 한 것입니다.

> 처음 만들었을 때 이 시험이 **`1080×1920` 을 오류코드로 잘못 잡았습니다.**
> 해상도지 오류코드가 아닙니다. 문서에 실제로 있는 코드 값만 보도록 고쳤고,
> 고친 뒤 「1080×1920 은 통과 / 1303 은 잡음」 을 따로 확인했습니다.

**「입력칸 이름이 잘리지 않는다」** — 이름칸 너비를 고정했더니 설정 화면에서
`대본 만들기 (Claude` 처럼 글자가 잘렸습니다. 화면 사진을 보고 발견했습니다.
너비를 화면별로 정할 수 있게 고쳤고, **일부러 좁혀서 시험이 실제로 잡아내는지 확인**했습니다.

```
[설정] '대본 만들기 (Claude)'   — 139px 필요한데 132px
[설정] '이미지 만들기 (Gemini)' — 154px 필요한데 132px
```

## 4. 화면 사진을 보고 고친 것

사진을 찍어 눈으로 보지 않았으면 못 찾았을 것들입니다.

| 문제 | 원인 | 고침 |
|---|---|---|
| 안내 상자 왼쪽에 `(` 자국 | 둥근 모서리와 한쪽 테두리를 같이 주면 Qt 가 괄호 모양을 그림 | 테두리 대신 **진짜 막대 위젯** |
| 입력칸 왼쪽 끝이 줄마다 어긋남 | 이름 길이에 따라 칸이 밀림 | 이름칸 너비 **고정** |
| 설정 화면 이름이 잘림 | 고정 너비가 긴 이름에 모자람 | 화면별 너비 + **잘림 시험** |
| 표 머리글만 가운데 정렬 | 기본값 | 내용과 같이 왼쪽 |
| 표 버튼이 테두리에 닿음 | 마지막 칸이 좁음 | 너비 확보 + 여백 |
| 상태 색이 안 나옴 | 글자색을 검정으로 덮어씀 | 완료=초록 · 실패=빨강 · 진행=주황 |

## 5. 아직 안 되는 것 — 화면만 있습니다

**버튼을 눌러도 실제로는 아무것도 만들지 않습니다.**

| 화면 | 지금 | 언제 진짜가 되나 |
|---|---|---|
| 대본 확인에 보이는 5장면 | 미리 넣어둔 **예시** | Stage 4 |
| 작업 목록의 4줄 | 미리 넣어둔 **예시** | Stage 3 (SQLite) |
| 설정의 열쇠 칸 | **잠가 뒀습니다** — 저장할 곳이 없어서 | Stage 3 (DPAPI) |
| 예상 비용 | "요금표를 아직 못 읽었습니다" | Stage 4 |
| 캐릭터 화면 | **진짜입니다** — `character_profile.json` 을 읽습니다 | 이미 됨 |

캐릭터 화면만 실제 파일을 읽습니다. 그래서 **기준 이미지 3장이 없다는 것과
색 6칸이 비어 있다는 것을 화면이 직접 알려줍니다.** 읽기만 하고 쓰지 않습니다.

## 6. 사장님 PC에서 확인하시는 법

깃허브에서 받으신 뒤 (`받아오기.ps1`), PowerShell 에서:

```powershell
cd 내문서\블로그작업\orak-shortform-studio
python -m venv .venv
.venv\Scripts\activate
pip install PySide6==6.8.1
python -m app.main
```

창이 뜨면 왼쪽 메뉴 4개를 눌러보세요.

> **당근 카드뉴스(A) 와 `venv` 를 따로 씁니다** (분리규칙 §3-7).
> 위 명령은 이 폴더 안에 `.venv` 를 새로 만듭니다. A 것과 섞이지 않습니다.

리눅스·맥에서 화면 없이 확인하시려면:

```
python tests/test_ui_flow.py             ← 눌러보기만
python tests/test_ui_flow.py ./사진      ← 화면 사진까지 저장
```
