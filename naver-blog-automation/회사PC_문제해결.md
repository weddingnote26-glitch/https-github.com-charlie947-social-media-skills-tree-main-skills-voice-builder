# 회사 PC 문제 해결

> 이 문서는 **naver-blog-automation** 프로그램 전용입니다.

---

## 먼저 이것부터

오류가 나면 **창이 저절로 닫히지 않습니다.** 그대로 두고 화면을 읽어 주세요.

1. **빨간 글씨**를 찾습니다 → 거기가 원인입니다
2. 아래 목록에서 같은 내용을 찾습니다
3. 못 찾으면 `logs\실행기록_*.log` 중 **가장 최근 파일**을 열어 그대로 전달해 주세요

---

## 창이 열렸다가 바로 닫힐 때

바로가기가 아니라 `.bat` 파일을 **두 번 클릭**해 보세요.
같은 내용이 뜨고 이번에는 닫히지 않습니다.

그래도 닫힌다면 `logs\` 폴더의 가장 최근 `실행기록_*.log` 를 열어 보세요.
화면에 나왔던 내용이 그대로 들어 있습니다.

---

## `이 시스템에서 스크립트를 실행할 수 없으므로`

`.ps1` 파일을 직접 실행할 때만 나옵니다.

**해결 1 (권장):** 바탕화면 바로가기나 `.bat` 파일로 실행하세요. 이 오류가 나지 않습니다.

**해결 2:** PowerShell 창에서 **한 번만** 아래를 실행하세요.

```bash
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

---

## `프로그램 파일을 찾지 못했습니다`

폴더를 옮기셨거나, 실행 파일만 따로 복사하신 경우입니다.

`start-naver-blog-automation.bat` 은 **반드시 `naver-blog-automation` 폴더 안에** 있어야 합니다.

폴더를 옮기셨다면 새 위치에서 **`바탕화면_바로가기_만들기.ps1`** 을 다시 실행하세요.

---

## `파이썬을 찾지 못했습니다` / 설치가 안 될 때

### 파이썬이 없는 경우

<https://www.python.org/downloads/> 에서 설치하시고,
설치 첫 화면에서 **"Add Python to PATH"** 를 꼭 체크하세요.

설치 후 **PowerShell 창을 닫고 새로 여세요.**

### 파이썬은 있는데 설치가 중간에 멈추는 경우

회사 보안 프로그램이나 사내 네트워크가 막는 경우가 대부분입니다.

확인용으로 PowerShell 창에서 아래를 실행해 보세요.

```bash
python -m pip install --upgrade pip
```

| 나온 내용 | 원인 | 해결 |
|---|---|---|
| `SSL` / `CERTIFICATE_VERIFY_FAILED` | 회사 보안 장비가 검사 중 | IT 담당자에게 **사내 인증서 등록** 요청 |
| `ProxyError` / `Connection timed out` | 사내 프록시 | IT 담당자에게 **프록시 주소** 확인 |
| `Access is denied` | 폴더 권한 | 폴더를 `내 문서` 아래로 옮기기 |

### 그래도 안 되면 (수동 설치)

프로그램 폴더에서 PowerShell 창을 열고 순서대로:

```bash
py -m venv .venv
```

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 한글이 `???` 나 네모로 깨져 보일 때

`.ps1` 파일을 메모장 등으로 열어 **저장한 적이 있는지** 확인해 주세요.
저장할 때 인코딩이 바뀌면 깨집니다.

깃허브에서 원래 파일을 다시 받으면 해결됩니다.
한 단계 위 폴더의 **`받아오기.ps1`** 을 실행하세요.

---

## 바로가기가 안 만들어질 때

회사 보안 정책이 바로가기 생성을 막는 경우가 있습니다.

**직접 만드는 방법:**

1. `start-naver-blog-automation.bat` 에서 **오른쪽 클릭**
2. **"바로 가기 만들기"** 선택
3. 만들어진 파일을 **바탕화면으로 끌어다 놓기**
4. 이름을 **`네이버 블로그 자동화 실행`** 으로 바꾸기

---

## 바로가기를 눌러도 아무 반응이 없을 때

바로가기가 **없어진 폴더**를 가리키고 있을 수 있습니다.

바로가기에서 **오른쪽 클릭 → 속성 → 대상** 을 보세요.
그 경로에 파일이 실제로 있는지 확인하시고,
없다면 프로그램 폴더의 **`바탕화면_바로가기_만들기.ps1`** 을 다시 실행하세요.

---

## `이 폴더가 구글 드라이브 안에 있습니다` 경고

프로그램 폴더가 클라우드 동기화 폴더 안에 있습니다.
이대로 두면 작업 기록(`.git`)이 깨집니다.

폴더 전체를 **`내 문서\블로그작업`** 으로 옮겨 주세요.
문서·보고서는 클라우드에 그대로 두셔도 괜찮습니다.

---

## 집에서 한 작업이 회사에 안 보일 때

1. 집 PC에서 **`올리기.ps1`** 을 실행했는지 확인
2. 회사 PC에서 **`받아오기.ps1`** 을 실행
3. 그래도 안 보이면 브랜치가 맞는지 확인합니다

프로그램 폴더에서 PowerShell 창을 열고:

```bash
git branch --show-current
```

**`claude/work-environment-setup-qkurkt`** 라고 나와야 정상입니다.

다르게 나오면:

```bash
git checkout claude/work-environment-setup-qkurkt
```

---

## 깃허브 최신 버전 받아오기

한 단계 위 폴더(`내 문서\블로그작업`)의 **`받아오기.ps1`** 을
오른쪽 클릭 → "PowerShell에서 실행".

직접 명령어로 하시려면 프로그램 폴더에서:

```bash
git pull origin claude/work-environment-setup-qkurkt
```

> 받아온 뒤에 새 패키지가 필요할 수 있습니다.
> 바로가기를 실행하면 자동으로 확인하니 따로 하실 일은 없습니다.

---

## 로그인 정보 관련 주의

| 하면 안 되는 것 | 이유 |
|---|---|
| 네이버 비밀번호를 파일에 적기 | 깃허브에 올라갈 수 있습니다 |
| `private\` 폴더를 다른 PC로 복사 | 로그인 정보가 그대로 딸려 갑니다 |
| API 키를 `settings.yaml` 에 적기 | 이 파일도 실수로 올라갈 수 있습니다 |
| 로그 파일을 그대로 남에게 보내기 | 폴더 경로·PC 이름이 들어 있습니다 |

> `private\`, `config\settings.yaml`, `logs\`, `.env` 는
> 이미 **자동으로 차단**되어 있어 깃허브에 올라가지 않습니다.

---

## 그래도 안 될 때 — 전달해 주실 것

아래 3가지를 알려 주시면 원인을 찾기 쉽습니다.

1. `logs\` 폴더에서 **가장 최근** `실행기록_*.log` 파일
2. 화면에 나온 **빨간 글씨** 전체
3. 아래 명령 결과

```bash
python --version; git --version; git branch --show-current
```
