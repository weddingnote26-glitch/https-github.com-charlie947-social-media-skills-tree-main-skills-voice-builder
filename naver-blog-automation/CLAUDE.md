# Claude Code 작업 지침 — 네이버 블로그 콘텐츠 시스템

이 저장소에서 작업할 때 지켜야 할 것들입니다.

## 이 프로젝트가 하는 일

두 개의 네이버 블로그에 주 6회씩(월~토) 글을 올리기 위한 도구입니다.
**원고 생성 → 사실 확인 → 검수 → 사람 승인 → 네이버 예약 발행** 순서로 일합니다.

| 채널 키 | 이름 | 블로그 ID | 발행 시각 |
|---|---|---|---|
| `coin` | 친절한 코인 설명서 | `dylankim26` | 월~토 07:00 |
| `stock` | 오락 5070 경제공부소 | `playorak` | 월~토 07:30 |

## 절대 하면 안 되는 것

1. **네이버 글쓰기 API를 쓰지 마세요.** 2020년 5월 6일에 종료됐습니다.
   옛 문서(`naver-openapi-guide`)에 `/blog/writePost` 가 남아 있지만 동작하지 않습니다.
   비공식 내부 API를 찾아 쓰는 것도 금지입니다.
2. **네이버 계정 정보를 코드나 설정 파일에 넣지 마세요.**
3. **CAPTCHA·본인인증·보안 경고를 우회하는 코드를 쓰지 마세요.**
4. **출처 없는 가격·지수·환율·금리를 지어내지 마세요.** `확인 필요` 로 남기세요.
5. **`config/style_*.md` 의 양식을 추측으로 채우지 마세요.**
   실제 게시물 샘플을 받았을 때만 채웁니다. 그전에는 `status: awaiting_samples` 로 둡니다.
6. **두 채널에 같은 소재나 같은 문장을 쓰지 마세요.**
7. **사람의 승인 없이 공개 발행하지 마세요.**

## 원고를 쓸 때

주간 작업 지시 파일(`output/<주차>/작업지시_이번주원고.md`)을 읽고 순서대로 씁니다.
글 하나마다 **그 폴더의 `brief.md` 를 먼저 읽으세요.** 채널·독자·문체·주제가 적혀 있습니다.

### 만들어야 하는 파일

| 파일 | 내용 |
|---|---|
| `post.md` | 최종 원고 (앞머리 메타데이터 + 본문) |
| `sources.md` | 참고 자료와 사실 확인 내역 |
| `image_prompts.md` | 이미지 프롬프트와 대체 텍스트 |

`post.html`, `checklist.md`, `발행카드.md` 는 스크립트가 만듭니다. 직접 만들지 마세요.

### post.md 형식

`templates/post_template.md` 를 따릅니다. 앞머리(front matter)에 반드시 넣을 것:

- `title_candidates` — 검색 키워드를 자연스럽게 반영한 제목 후보 **3개**
- `title` — 그중 고른 최종 제목
- `hashtags` — 5~10개
- `images` — `file`(영문·숫자 파일명), `position`, `alt` 를 각각 채움
- `data_asof` — 시황·뉴스 글이면 `2026-08-24 07:00 KST` 형식. 아니면 `null`

본문에 반드시 넣을 것:

- 100자 이내 도입부
- 소제목 3~6개 (`## `)
- 이미지 자리 표시 `[이미지:파일명]` — `images` 의 `file` 과 이름이 같아야 합니다
- 초보자를 위한 용어 설명
- 핵심 내용 요약
- 독자에게 던지는 질문
- 채널별 투자 유의 문구 (`channel_profiles.yaml` 의 `disclaimer` 를 그대로)

### 수치를 쓸 때

본문에 금액·지수·환율·금리·비율을 쓰려면 **반드시** `sources.md` 의
`## 확인한 수치` 표에 서로 다른 출처 2곳과 함께 올려야 합니다.
교차확인 열에 `✓` 가 없으면 `scripts/review.py` 가 발행을 막습니다.

확인하지 못했다면 숫자를 지어내지 말고 본문에 `확인 필요` 라고 쓰세요.

### 설명용 예시 숫자는 예시임을 밝히세요

가르치는 글에서 가정한 숫자를 들 때는 **예시라는 것이 문장에 드러나야** 합니다.
독자가 예시를 실제 시세로 오해하지 않게 하기 위해서입니다.

| 이렇게 쓰면 | 결과 |
|---|---|
| `100억 원을 넣어 10억 원을 번 회사가 있습니다` | 출처를 요구받아 검수에서 막힙니다 |
| `가령 100억 원을 넣어 10억 원을 벌었다고 해 봅시다` | 예시로 인식되어 통과합니다 |

인식되는 표시어: `예를 들`, `예로 들`, `예시`, `가정`, `만약`, `가령`,
`라고 해 봅`, `라고 치면`, `쳐 봅시다`, `가상의`, `임의로`

시황·뉴스 글은 예시 범위를 **문단 하나**로 좁게 봅니다.
용어·개념 설명 글은 **그 소제목 안**으로 넓게 봅니다.

## 검수를 통과시키는 법

`python scripts/review.py` 가 15가지를 검사합니다.
`막힘`이 하나라도 있으면 승인할 수 없습니다. 각 글 폴더의 `checklist.md` 에 목록이 나옵니다.

자주 걸리는 것:
- 소제목이 3개 미만
- 해시태그가 5개 미만이거나 10개 초과
- 투자 유의 문구 누락
- 본문 수치에 출처가 없음
- 앞머리의 `blog_id` 가 채널과 다름 (**채널 혼동 — 가장 위험**)
- 두 채널 글이 25% 이상 닮음

## 명령 모음

```bash
python scripts/schedule_week.py      # 주간 편성 만들기
python scripts/generate_week.py      # 원고 작업 지시서 만들기
python scripts/factcheck.py          # 수치 출처 검사
python scripts/review.py             # 15가지 자동 검수
python scripts/approve.py            # 사람 승인
python scripts/prepare_publish.py    # 예약 발행 자료 준비
python scripts/publish_status.py     # 상태 보기
python scripts/menu.py               # 번호 선택 메뉴
```

## 코드를 고칠 때

- 경로는 **프로젝트 루트 기준 상대경로**만 씁니다. 절대경로 금지.
- 파일 입출력은 `scripts/common.py` 의 `read_text` / `write_text` 를 씁니다.
  (UTF-8 고정, 개행 `\n` 통일 — Windows 한글 경로 대응)
- 화면 출력은 `common.say/ok/info/warn/error/header` 를 씁니다.
- 표를 그릴 때는 `common.pad` / `common.clip` 을 씁니다. (한글은 두 칸 폭)
- 새 설정값은 `config/settings.example.yaml` 에도 함께 추가합니다.
- 사용자에게 보이는 글은 **쉬운 한국어**로 씁니다. 비개발자가 읽습니다.

## 글 양식 분석을 요청받으면

사용자가 블로그 게시물 샘플을 주면 `config/style_coin.md` 또는
`config/style_stock.md` 를 채웁니다.

1. 앞머리를 `status: analyzed`, `analyzed_at`, `sample_count` 로 갱신
2. `분석 결과` 표의 각 항목을 **실제로 확인한 것만** 채우기
   (확인 못 한 항목은 `미확인` 그대로 두기)
3. `분석에 사용한 게시물` 표에 어떤 글을 봤는지 기록
4. `임시 골격 (⚠ 분석 결과가 아닙니다)` 절을 실제 양식으로 교체
5. 필요하면 `config/settings.yaml` 의 `review.min_chars` / `max_chars` 를
   실제 글자 수에 맞게 조정하도록 사용자에게 안내

기존 문장을 그대로 베끼지 말고, 양식(구조·길이·말투)만 따릅니다.
