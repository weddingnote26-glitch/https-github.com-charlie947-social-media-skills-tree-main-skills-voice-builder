# Claude Code 작업 지침 — 네이버 블로그 콘텐츠 시스템

이 저장소에서 작업할 때 지켜야 할 것들입니다.

## 이 프로젝트가 하는 일

두 개의 네이버 블로그에 주 6회씩(월~토) 글을 올리기 위한 도구입니다.
**원고 생성 → 사실 확인 → 검수 → 사람 승인 → 네이버 예약 발행** 순서로 일합니다.

| 채널 키 | 이름 | 블로그 ID | 발행 시각 |
|---|---|---|---|
| `coin` | 친절한 코인 설명서 | `dylankim26` | 월~토 08:30 |
| `stock` | 오락 5070 경제공부소 | `playorak` | 월~토 07:30 |

## 절대 하면 안 되는 것

1. **네이버 글쓰기 API를 쓰지 마세요.** 2020년 5월 6일에 종료됐습니다.
   옛 문서(`naver-openapi-guide`)에 `/blog/writePost` 가 남아 있지만 동작하지 않습니다.
   비공식 내부 API를 찾아 쓰는 것도 금지입니다.
1-1. **`post.html` 을 업로드 기준으로 삼지 마세요.**
   스마트에디터 ONE 은 HTML 글쓰기를 지원하지 않습니다.
   `post.html` 은 눈으로 확인하는 용도이며, 실제 업로드는
   `publish/` 폴더의 `body.txt` + `blocks.yaml` 을 씁니다.
1-2. **이미지를 클립보드 복사나 외부 URL 로 넣지 마세요.**
   네이버 포토 업로더로 파일을 직접 올려야 합니다.
2. **네이버 계정 정보를 코드나 설정 파일에 넣지 마세요.**
3. **CAPTCHA·본인인증·보안 경고를 우회하는 코드를 쓰지 마세요.**
4. **출처 없는 가격·지수·환율·금리를 지어내지 마세요.** `확인 필요` 로 남기세요.
5. **`config/style_*.md` 의 양식을 추측으로 채우지 마세요.**
   실제 게시물 샘플을 받았을 때만 채웁니다. 그전에는 `status: awaiting_samples` 로 둡니다.
6. **두 채널에 같은 소재나 같은 문장을 쓰지 마세요.**
7. **사람의 승인 없이 공개 발행하지 마세요.**

## 채널마다 틀이 다릅니다

### 친절한 코인 설명서 — 템플릿이 **두 개**입니다

카테고리에 따라 인사말·제목·소제목 형식이 전부 다릅니다. **섞어 쓰면 안 됩니다.**
`config/channel_profiles.yaml` 의 `templates` 에 정리되어 있습니다.

| | A. 모닝 시황 | B. 매매팁·투자마인드 |
|---|---|---|
| 슬롯 | 월·수·토 (시황/이슈/복습) | 화·목·금 (기초/마인드/위험) |
| 카테고리 | 코인시황뉴스 | 코인투자마인드 |
| 말머리 | `[친절한코인설명서]` | `[코린이 매매팁]` |
| 제목 | 27자 고정 형식 | 독자 질문 + 개념 + 이모지 |
| 인사말 | "…소중한 시드를 안전하게 지켜드리는…" | "…10년 차 실전 투자자, 여러분의 멘토…" |
| 소제목 | `1. 📌 제목 (부제)` — 숫자 먼저 | `📊 1. 제목` — 이모지 먼저 |
| 소제목 내용 | 4개 **고정** (3줄요약/시황분석/매매가이드/아웃트로) | 3개 + `💡 오늘의 친절한 한 줄 요약` |
| 끝 | 유의문구 | 관련 글 링크 4개 |

### 오락 5070 경제공부소 — 소제목 4개 고정으로 보임

`아주 쉽게 설명해 드릴게요` → `주식에서는 어떻게 활용할까요?`
→ `초보자가 많이 하는 실수` → `오늘의 N줄 정리`

> 표본 1편이라 확정은 아닙니다. 샘플이 더 오면 확인합니다.

## 두 채널 모두 — 반드시 지킬 것

**비유를 꼭 넣습니다.** 두 채널의 공통 핵심 기법입니다.
일상 사물로 비유하고, 금융 비유는 쓰지 않습니다.

| 채널 | 실제 사용 예 |
|---|---|
| 코인 | 물웅덩이 / 줄다리기 / 피자 한 판 / 흡성대법 |
| 경제 | 양초 / 줄다리기 / 해와 그늘 |

**문장을 짧게 씁니다.** 코인 평균 31자, 경제 평균 35자.
두 채널 모두 90자 넘는 문장이 거의 없습니다.

**괄호로 뜻을 풉니다.** `도미넌스(Dominance)`, `빨간 막대(양봉, 陽棒)`

## 원고를 쓸 때

주간 작업 지시 파일(`output/<주차>/작업지시_이번주원고.md`)을 읽고 순서대로 씁니다.
글 하나마다 **그 폴더의 `brief.md` 를 먼저 읽으세요.** 채널·독자·문체·주제가 적혀 있습니다.

### 만들어야 하는 파일

| 파일 | 내용 |
|---|---|
| `post.md` | 최종 원고 (앞머리 메타데이터 + 본문) |
| `sources.md` | 참고 자료와 사실 확인 내역 |
| `image_prompts.md` | 이미지 프롬프트와 대체 텍스트 |

`post.html`, `checklist.md`, `발행카드.md` 는 스크립트가 만듭니다. 직접 만들지 마세요.

### post.md 형식

`templates/post_template.md` 를 따릅니다. 앞머리(front matter)에 반드시 넣을 것:

- `title_candidates` — 검색 키워드를 자연스럽게 반영한 제목 후보 **3개**
- `title` — 그중 고른 최종 제목
- `hashtags` — 5~10개
- `images` — `file`(영문·숫자 파일명), `position`, `alt` 를 각각 채움
- `data_asof` — 시황·뉴스 글이면 `2026-08-24 07:00 KST` 형식. 아니면 `null`

본문에 반드시 넣을 것:

- 100자 이내 도입부
- 소제목 3~6개 (`## `)
- 이미지 자리 표시 `[이미지:파일명]` — `images` 의 `file` 과 이름이 같아야 합니다
- 초보자를 위한 용어 설명
- 핵심 내용 요약
- 독자에게 던지는 질문
- 채널별 투자 유의 문구 (`channel_profiles.yaml` 의 `disclaimer` 를 그대로)

### 수치를 쓸 때

본문에 금액·지수·환율·금리·비율을 쓰려면 **반드시** `sources.md` 의
`## 확인한 수치` 표에 올려야 합니다.
교차확인 열에 `✓` 가 없으면 `scripts/review.py` 가 발행을 막습니다.

확인하지 못했다면 숫자를 지어내지 말고 본문에 `확인 필요` 라고 쓰세요.

#### 시세의 기준 출처는 트레이딩뷰입니다 (2026-08-22 사용자 지정)

시장 주가·시장 동향·시세는 **https://kr.tradingview.com/** 을 봅니다.
자주 보는 항목의 주소는 `config/data_sources.yaml` 에 있습니다.

필요한 출처 수가 자료 종류에 따라 다릅니다.

| 종류 | 예 | 필요한 출처 |
|---|---|---|
| 화면에서 읽는 값 (`quote`) | 가격, 지수, 환율, 등락률, 도미넌스 | **트레이딩뷰 한 곳** |
| 사건·발표 (`claim`) | ETF 승인, 금리 인하, 규제 발표, 상장·폐지 | **서로 다른 두 곳** |

출처 1 칸에 `트레이딩뷰` / `TradingView` / `kr.tradingview.com` 중 하나가
적혀 있어야 검사기가 시세로 알아봅니다. 없으면 사건으로 보고 2곳을 요구합니다.

**Claude Code 는 트레이딩뷰에 접속할 수 없습니다.** (작업 환경에서 막혀 있음)
시세는 사람이 화면에서 읽어 `sources.md` 에 적어 주셔야 합니다.
`python scripts/quotes.py` 를 쓰면 열어 볼 주소와 붙여 넣을 표가 나옵니다.
추측으로 채우지 마세요.

### 설명용 예시 숫자는 예시임을 밝히세요

가르치는 글에서 가정한 숫자를 들 때는 **예시라는 것이 문장에 드러나야** 합니다.
독자가 예시를 실제 시세로 오해하지 않게 하기 위해서입니다.

| 이렇게 쓰면 | 결과 |
|---|---|
| `100억 원을 넣어 10억 원을 번 회사가 있습니다` | 출처를 요구받아 검수에서 막힙니다 |
| `가령 100억 원을 넣어 10억 원을 벌었다고 해 봅시다` | 예시로 인식되어 통과합니다 |

인식되는 표시어: `예를 들`, `예로 들`, `예시`, `가정`, `만약`, `가령`,
`~고 해 봅`, `~고 해 볼게`, `~고 치면`, `쳐 봅시다`, `쳐 볼게`,
`가상의`, `임의로`, `셈 치`

`~고 해 봅` 은 어미를 가리지 않습니다.
`1만원이라고 해 봅시다` 도, `100원을 벌었다고 해 봅시다` 도 모두 예시로 봅니다.

시황·뉴스 글은 예시 범위를 **문단 하나**로 좁게 봅니다.
용어·개념 설명 글은 **그 소제목 안**으로 넓게 봅니다.

## 검수를 통과시키는 법

`python scripts/review.py` 가 15가지를 검사합니다.
`막힘`이 하나라도 있으면 승인할 수 없습니다. 각 글 폴더의 `checklist.md` 에 목록이 나옵니다.

자주 걸리는 것:
- 소제목이 3개 미만
- 해시태그가 5개 미만이거나 10개 초과
- 투자 유의 문구 누락
- 본문 수치에 출처가 없음
- 앞머리의 `blog_id` 가 채널과 다름 (**채널 혼동 — 가장 위험**)
- 두 채널 글이 25% 이상 닮음

## 업로드 패키지 (publish/)

`prepare_publish.py` 가 승인된 글마다 만듭니다. 직접 손으로 만들지 마세요.

| 파일 | 내용 |
|---|---|
| `title.txt` | 순수 텍스트 제목 |
| `body.txt` | 숨은 태그가 없는 순수 텍스트 본문 |
| `blocks.yaml` | 문단·소제목·이미지·목록·구분선의 입력 순서 |
| `image_order.csv` | 이미지 파일과 삽입 위치, 대체 텍스트 |
| `publish_settings.yaml` | 채널·카테고리·공개설정·예약일시·태그·본문지문 |
| `upload_checklist.md` | 사람이 따라가는 순서표 (0단계 = 블로그 ID 7가지 확인) |
| `result.json` | 단계별 진행 기록, 올린 이미지 목록, 실패 이력 |

블록 형식은 `scripts/blocks.py` 가 정합니다.
`paragraph` / `heading` / `image` / `list` / `divider` / `quote` / `hashtags`.

## 상태 흐름 (10단계)

```
draft → fact_checked → reviewed → approved
     → editor_filled → draft_saved
     → reservation_requested → reservation_verified
     → published → post_publish_verified
```

- `approved` 이전에는 네이버 쪽 단계로 갈 수 없습니다. (`common.can_touch_naver`)
- 단계를 건너뛸 수 없습니다. (`common.can_advance`)
- 어느 단계에서든 `failed` 로 빠질 수 있고, 고친 뒤 그 단계부터 이어서 합니다.

## 발행 전 반드시 검사하는 것

`scripts/conflicts.py` 가 `prepare_publish.py` 와 브라우저 작업 앞에서 돌아갑니다.

**중복** — 같은 post_id / 같은 제목 / 같은 채널·날짜 / 본문 해시 일치 /
본문 60% 이상 유사 / 이미 네이버에 올라간 기록(naver_log_no, post_url)

**예약 충돌** — 이미 지난 시각 / 월~토가 아님 / 폴더 날짜와 불일치 /
원고 요일과 불일치 / 공휴일 설정 / 같은 채널·같은 시각 중복 / 최소 발행 간격


## 코드를 고칠 때

- 경로는 **프로젝트 루트 기준 상대경로**만 씁니다. 절대경로 금지.
- 파일 입출력은 `scripts/common.py` 의 `read_text` / `write_text` 를 씁니다.
  (UTF-8 고정, 개행 `\n` 통일 — Windows 한글 경로 대응)
- 화면 출력은 `common.say/ok/info/warn/error/header` 를 씁니다.
- 표를 그릴 때는 `common.pad` / `common.clip` 을 씁니다. (한글은 두 칸 폭)
- 새 설정값은 `config/settings.example.yaml` 에도 함께 추가합니다.
- 사용자에게 보이는 글은 **쉬운 한국어**로 씁니다. 비개발자가 읽습니다.

## 글 양식 분석을 요청받으면

### 표본이 `samples/` 에 있을 때 (권장)

사용자가 `python scripts/fetch_samples.py` 를 실행하면
`samples/coin/` 과 `samples/stock/` 에 글이 저장됩니다.

각 파일 앞머리에 **이미 재어 놓은 값**이 있습니다. 다시 세지 말고 그걸 쓰세요.

```yaml
title_chars: 49            # 제목 글자 수
body_chars: 1383           # 본문 글자 수 (공백 제외)
avg_sentence_chars: 35     # 문장 평균 길이
heading_count: 4
headings: ["아주 쉽게 설명해 드릴게요", ...]
image_count: 3
tags: [주식초보, 양봉음봉, ...]
```

분석 방법:
1. 채널별로 모든 표본의 값을 모아 **중간값과 범위**를 냅니다.
2. `headings` 목록을 비교해 **반복되는 소제목이 있는지** 봅니다.
   여러 글에 같은 소제목이 나오면 고정 템플릿입니다.
3. 본문에서 반복되는 표현(인사말, 마무리, 괄호 뜻풀이 등)을 찾습니다.
4. 표본이 3편 미만이면 `confidence: low` 로 두고 그렇게 밝힙니다.
5. 잰 값으로 `channel_profiles.yaml` 의 `review_targets` 를 보정하고
   `calibrated_from` 에 표본 수를 적습니다.

### 표본이 없고 사용자가 본문을 붙여넣었을 때

같은 항목을 직접 재되, **본 것만** 적습니다.
이미지 배치처럼 텍스트로 알 수 없는 것은 `미확인` 으로 남기고,
화면 캡처를 요청하세요.

### 공통 규칙

사용자가 블로그 게시물 샘플을 주면 `config/style_coin.md` 또는
`config/style_stock.md` 를 채웁니다.

1. 앞머리를 `status: analyzed`, `analyzed_at`, `sample_count` 로 갱신
2. `분석 결과` 표의 각 항목을 **실제로 확인한 것만** 채우기
   (확인 못 한 항목은 `미확인` 그대로 두기)
3. `분석에 사용한 게시물` 표에 어떤 글을 봤는지 기록
