# 네이버 블로그 주간 콘텐츠 제작 도우미

두 블로그에 매주 월~토 12편을 올리기 위한 도구입니다.
집과 회사 어느 PC에서든 이어서 작업할 수 있습니다.

| 채널 | 블로그 | 독자 |
|---|---|---|
| 친절한 코인 설명서 | [blog.naver.com/dylankim26](https://blog.naver.com/dylankim26) | 코인 투자를 막 시작한 분 |
| 오락 5070 경제공부소 | [blog.naver.com/playorak](https://blog.naver.com/playorak) | 50~70대 주식·경제 입문자 |

## 먼저 알아 두실 것

### 네이버는 글을 자동으로 올려주는 공식 기능이 없습니다

네이버에 **블로그 글쓰기 API가 있었지만 2020년 5월 6일에 종료**되었습니다.
종료 이유는 *"광고성 글을 API로 대량 제작·게재하는 것을 막기 위해"* 였습니다.

> 옛날 개발 문서에는 아직 `/blog/writePost` 라는 항목이 남아 있어
> 지금도 되는 것처럼 보입니다. 하지만 실제로는 동작하지 않습니다.
> 2026년 6월에 나온 NAVER API HUB 에도 글쓰기 기능은 없고 검색 기능만 있습니다.

### HTML을 붙여넣지 않습니다

네이버 **스마트에디터 ONE 은 HTML 글쓰기를 지원하지 않습니다.**
HTML을 통째로 붙여넣으면 서식이 깨지거나 숨은 태그가 섞일 수 있습니다.

그래서 이 도구는 원고를 **편집기 구성요소 단위로 쪼개서** 준비합니다.

| 파일 | 무엇인가 |
|---|---|
| `publish/title.txt` | 제목 (순수 텍스트) |
| `publish/body.txt` | 본문 (숨은 태그 없는 순수 텍스트) |
| `publish/blocks.yaml` | 문단·소제목·이미지·목록을 넣는 순서 |
| `publish/images/` | 포토 업로더로 올릴 이미지 (01_, 02_ … 순서대로) |
| `publish/image_order.csv` | 이미지가 들어갈 자리와 대체 텍스트 |
| `publish/publish_settings.yaml` | 채널·카테고리·공개설정·예약일시·태그 |
| `publish/upload_checklist.md` | **사람이 따라가는 순서표** |
| `publish/result.json` | 어디까지 했는지 기록 |

> `post.html` 도 만들어지지만 **눈으로 확인하는 용도**입니다.
> 네이버에 붙여넣지 마세요.

### 이미지는 포토 업로더로 올립니다

이미지를 복사·붙여넣기로 넣으면, 원본 파일이 옮겨지거나 지워졌을 때
글에서 이미지가 사라질 수 있습니다.
반드시 편집기의 **사진 단추(포토 업로더)** 로 파일을 직접 올려 주세요.

### 전체 흐름

```
원고 생성 → 사실 확인 → 자동 검수 → 사람 승인
   → 업로드 패키지 만들기 → 편집기에 입력 → 비공개 저장 → 화면 확인
   → 예약 걸기 → 예약 목록 확인 → 발행일에 실제 게시 확인
```

**"편집기에 입력됨"과 "예약 걸림"과 "실제로 올라감"은 서로 다른 일입니다.**
그래서 상태를 따로 관리합니다.

```
초안 → 사실확인 → 검수완료 → 승인됨
     → 편집기입력 → 비공개저장 → 예약요청 → 예약확인
     → 발행됨 → 발행확인완료
```

문제가 생기면 `실패` 로 기록하고, 고친 뒤 **멈춘 곳부터 이어서** 할 수 있습니다.

### 예약 발행은 네이버 공식 기능입니다

글쓰기 화면 우측 상단 **발행 → 예약** 에서 날짜와 시간을 고르면 됩니다.

## 처음 한 번만: 설치하기

### 1단계 — 파이썬 설치 (없다면)

[python.org/downloads](https://www.python.org/downloads/) 에서 내려받아 설치합니다.
설치 화면에서 **"Add Python to PATH"** 를 꼭 체크하세요.

### 2단계 — setup.ps1 실행

`setup.ps1` 파일에서 마우스 오른쪽 → **PowerShell에서 실행**

> "이 시스템에서 스크립트를 실행할 수 없으므로" 라는 오류가 나오면,
> PowerShell 창에 아래를 한 번 입력한 뒤 다시 실행하세요.
> ```
> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
> ```

설치 중에 **"이 PC를 뭐라고 부를까요?"** 라고 물어봅니다.
집 PC면 `집`, 회사 PC면 `회사` 라고 적어 주세요.

### 3단계 — 내 블로그 글 가져오기 ⚠ 중요

이 도구는 **두 블로그의 실제 글 양식을 알아야** 기존 글과 비슷한 모양으로
원고를 만듭니다. 양식을 지어내지 않기 위해, 확인 전에는 비워 둡니다.

`fetch_samples.ps1` 을 실행하거나, 메뉴에서 **0번**을 고르세요.

```
python scripts/fetch_samples.py
```

두 블로그의 **공개 RSS** 에서 최근 글 10편씩을 가져와 `samples/` 에 저장합니다.

- 로그인하지 않습니다. 공개된 글만 가져옵니다.
- 비공개 글은 가져올 수 없습니다.
- 추가 설치가 필요 없습니다.
- 네이버에 무리를 주지 않도록 글 사이에 잠깐씩 쉽니다.

가져온 뒤 Claude Code 에게 이렇게 말하세요.

```
samples/ 폴더의 글을 분석해서 style_coin.md 와 style_stock.md 를 채워줘
```

제목 길이, 문장 길이, 소제목 구성, 이미지 개수, 자주 쓰는 표현을 재어
`config/style_coin.md` 와 `config/style_stock.md` 에 기록합니다.
그 뒤로 만들어지는 원고는 그 양식을 따릅니다.

> **회사 방화벽이 막아서 안 된다면**
> 글 본문을 복사해서 Claude Code 에 그대로 붙여넣으셔도 됩니다.
> 이미지 배치까지 알려면 화면 캡처를 1~2장 함께 주세요.
> (본문 텍스트만으로는 이미지가 어디에 들어가는지 알 수 없습니다)

## 평소 쓰는 법

`run.ps1` 을 실행하면 메뉴가 나옵니다.

```
  0. 내 블로그 글 가져오기 (양식 분석용 — 처음에 한 번)

  1. 다음 주 콘텐츠 12편 생성
  2. 특정 게시물 다시 생성
  3. 전체 원고 검수
  4. 네이버 예약 발행 준비
  5. 승인된 글 예약 등록
  6. 발행 결과 확인
  7. 설정 변경
  8. 종료
```

### 한 주 작업 흐름

| 요일 | 할 일 | 메뉴 |
|---|---|---|
| 금~토 | 다음 주 12편 만들기 | 1번 |
| 토 | 검수하고 고치기 | 3번 |
| 토~일 | 승인하고 발행 자료 만들기 | 4번 |
| 일 | 네이버에 예약 걸기 | 5번 |
| 아무 때나 | 상태 확인 | 6번 |

### 글의 상태

글은 이 순서로만 올라갑니다. 건너뛸 수 없습니다.

```
초안 → 사실확인 → 검수완료 → 승인됨 → 예약등록 → 발행됨
```

**승인되지 않은 글은 예약 등록으로 넘어가지 않습니다.**

## 집과 회사에서 같이 쓰기

### 권장 방식 — 비공개 Git 저장소

**동기화되는 것** (프로그램과 설정)
- `scripts/` `templates/` — 프로그램
- `config/channel_profiles.yaml` — 채널 설정
- `config/style_coin.md` `config/style_stock.md` — 글 양식 분석 결과
- `config/settings.example.yaml` — 설정 예시
- `output/` — 만든 원고

**절대 동기화되지 않는 것** (`.gitignore` 로 막아 두었습니다)
- `private/` — 로그인 프로필, 쿠키
- `config/settings.yaml` — 이 PC만의 개인 설정
- `.env` `*.key` — API 키
- `logs/` `data/source_cache/` — 기록과 캐시

#### 처음 설정

```bash
# 집 PC (처음 올릴 때)
cd naver-blog-automation
git init
git add .
git commit -m "블로그 도구 첫 등록"
git remote add origin <비공개 저장소 주소>
git push -u origin main

# 회사 PC (처음 받을 때)
git clone <비공개 저장소 주소>
cd naver-blog-automation
.\setup.ps1        # 회사 PC에서도 한 번 실행해야 합니다
```

> `setup.ps1` 은 PC마다 한 번씩 실행해야 합니다.
> 파이썬 환경과 개인 설정 파일은 동기화되지 않기 때문입니다.

#### 매번 하는 일

```bash
# 작업 시작 전 — 상대편 PC에서 한 작업을 받아옵니다
git pull

#  … 작업 …

# 작업 마치고 — 반드시 올립니다
git add .
git commit -m "2026-W36 원고 12편"
git push
```

#### 작업이 충돌하지 않게

- **한 번에 한 PC에서만 작업하세요.** 양쪽에서 같은 주차를 동시에 건드리면 충돌합니다.
- 자리를 뜨기 전에 **꼭 `git push`** 하세요. 안 올린 작업은 그 PC에만 남습니다.
- 시작 전에 **꼭 `git pull`** 하세요.
- 충돌이 나면 원고 파일은 대부분 한쪽을 고르면 됩니다.
  `output/` 안의 파일은 서로 다른 날짜 폴더라 충돌이 잘 나지 않습니다.

### 대안 방식 — OneDrive / Google Drive

Git이 어렵다면 클라우드 폴더에 넣어 쓸 수도 있습니다.

#### 폴더 넣기

프로젝트 폴더째로 OneDrive 나 Google Drive 폴더 안으로 옮깁니다.

#### 로그인 폴더는 반드시 제외하세요 ⚠

`private` 폴더에는 **네이버 로그인 정보가 들어갑니다.**
이 폴더가 클라우드에 올라가면 로그인 정보가 밖으로 나갑니다.

**OneDrive에서 제외하는 법**
1. `private` 폴더에서 마우스 오른쪽
2. **"이 디바이스에서 항상 유지"** 해제
3. 또는 OneDrive 설정 → 백업 → 폴더 선택에서 제외

**Google Drive에서 제외하는 법**
1. Google Drive 설정 → 폴더 환경설정
2. `private` 폴더 동기화 해제

`config/settings.yaml` 도 PC마다 달라야 하므로 제외하는 편이 좋습니다.

#### 동시에 두 PC에서 실행하지 마세요

클라우드 동기화는 **실시간이 아닙니다.** 몇 초~몇 분 늦습니다.
양쪽에서 동시에 작업하면 이런 일이 생깁니다.

- 한쪽에서 쓴 원고가 다른 쪽 원고로 덮어씌워짐
- 같은 파일이 `post.md` 와 `post-충돌본.md` 로 둘 다 남음
- 진행 상태(`metadata.yaml`)가 뒤죽박죽 되어 승인이 풀림

**자리를 옮기기 전에 반드시 프로그램을 완전히 닫고,
동기화 아이콘이 "최신 상태" 가 될 때까지 기다리세요.**

#### 충돌 파일이 생겼다면

이런 이름의 파일이 보이면 충돌이 난 것입니다.
- `post-내컴퓨터-충돌본.md`
- `metadata (DESKTOP-XXX와 충돌이 발생한 사본).yaml`

처리 방법:
1. 두 파일을 모두 열어 봅니다.
2. 최근에 작업한 내용이 든 쪽을 남깁니다.
3. 남길 파일의 이름을 원래 이름(`post.md`)으로 바꿉니다.
4. 충돌본 파일은 지웁니다.
5. `run.ps1` → 3번(검수)을 다시 돌려 상태를 맞춥니다.

## 자주 묻는 것

**Q. 원고는 누가 쓰나요?**
기본값은 Claude Code 입니다. 메뉴 1번을 누르면 작업 지시서가 만들어지고,
Claude Code에게 *"작업지시_이번주원고.md 를 읽고 원고를 써줘"* 라고 하면 됩니다.
API 키가 필요 없고 추가 비용도 없습니다.

Claude API로 자동 생성하고 싶다면 `config/settings.yaml` 에서
`generation.mode` 를 `api` 로 바꾸고 `ANTHROPIC_API_KEY` 환경변수를 넣으세요.

**Q. 검수에서 막혔는데 어떻게 하나요?**
그 글 폴더의 `checklist.md` 를 열어 보세요. 고칠 목록이 적혀 있습니다.
고친 뒤 메뉴 3번을 다시 돌리면 됩니다.

**Q. 수치를 썼는데 자꾸 막힙니다.**
본문에 쓴 금액·지수·환율은 `sources.md` 의 표에
**서로 다른 출처 2곳**과 함께 올라가 있어야 합니다.
확인이 안 되면 그 숫자를 빼거나 `확인 필요` 라고 적으세요.
확인되지 않은 숫자를 그대로 올리지 않기 위한 장치입니다.

**Q. 같은 글을 두 번 올릴까 걱정됩니다.**
글마다 고유 ID와 본문 지문(해시)을 붙여 둡니다.
발행 준비 단계에서 같은 ID·같은 제목·같은 날짜·비슷한 본문이 있는지,
이미 네이버에 올라간 기록이 있는지 검사합니다. 걸리면 준비하지 않습니다.

**Q. 작업하다 중간에 멈추면 처음부터 다시 해야 하나요?**
아니요. 단계마다 기록이 남습니다. (`publish/result.json`)
다시 실행하면 멈춘 곳부터 이어서 하고, 이미 올린 이미지는 다시 올리지 않습니다.
멈춘 이유와 해야 할 일은 `publish/실패보고서.md` 에 적힙니다.

**Q. 검색에 바로 안 나옵니다. 실패인가요?**
아닙니다. 네이버는 글을 올린 뒤 검색에 반영되기까지 시간이 걸릴 수 있다고 안내합니다.
**게시 성공**과 **검색 노출**은 다른 일입니다. 이 도구도 따로 구분합니다.

**Q. 두 블로그가 같은 네이버 계정인가요, 다른 계정인가요?**
`config/settings.yaml` 의 `browser.account_mode` 에서 정합니다.
- `same_account` — 한 계정. 블로그를 전환한 뒤 ID를 다시 확인합니다.
- `separate_accounts` — 계정이 다름. 채널마다 브라우저 프로필을 나눕니다.

**Q. 브라우저 자동 등록은 안 쓰는 게 좋나요?**
네, 권하지 않습니다. 네이버가 자동 대량 발행을 막으려고 API를 종료했습니다.
발행 카드를 보고 직접 붙여넣는 쪽이 안전합니다.
꼭 쓰시겠다면 `config/settings.yaml` 에서 `browser.enabled` 를 `true` 로 바꾸고,
**처음에는 반드시 비공개로 1편만** 시험해 주세요.

**Q. 한글 폴더 이름이나 공백이 있어도 되나요?**
네, 됩니다. `내 문서\블로그 작업` 같은 경로에서도 동작하도록 만들었습니다.

**Q. 로그인 정보가 어디에 저장되나요?**
`private/browser-profile/` 폴더에만 저장되고, 이 폴더는 동기화되지 않습니다.
아이디와 비밀번호는 **어디에도 저장하지 않습니다.** 로그인은 매번 사람이 직접 합니다.

## 지키는 원칙

- 네이버 계정 비밀번호를 코드에 저장하지 않습니다.
- CAPTCHA나 보안 인증을 우회하지 않습니다.
- 없는 공식 API를 있는 것처럼 쓰지 않습니다.
- 출처 없는 가격·경제 수치를 만들지 않습니다.
- 다른 블로그 글의 문장을 복제하지 않습니다.
- 사람의 승인 없이 공개 발행하지 않습니다.
- 같거나 비슷한 글을 반복해서 올리지 않습니다.
- 매수·매도·수익을 보장하는 표현을 쓰지 않습니다.
- 시험 없이 12편을 한꺼번에 자동 등록하지 않습니다.
