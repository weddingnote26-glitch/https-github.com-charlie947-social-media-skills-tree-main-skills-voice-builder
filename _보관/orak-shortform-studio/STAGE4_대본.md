## 1. 모델과 요금 — 기억이 아니라 공식 자료로 확인했습니다

지시서 §0-2 5번이 「추측하지 말고 그 시점의 공식 문서를 확인하라」 고 했습니다.
Anthropic 공식 참고자료를 읽고 확인한 값입니다.

| | 값 |
|---|---|
| 기본 모델 | **`claude-opus-5`** |
| 입력 요금 | **$5.00** / 백만 토큰 |
| 출력 요금 | **$25.00** / 백만 토큰 |
| 한 편 대본 어림 | **약 97원** (입력 1,500 · 출력 2,500 토큰 기준) |

**모델 이름을 코드에 박지 않았습니다** (§2-4). 기본값 한 줄만 두고 설정에서 바꿉니다.
요금은 `assets/pricing.json` 에 넣었고, 바뀌면 그 파일만 고치면 됩니다.

> 당근 카드뉴스(A)도 같은 모델을 쓰지만 **키는 서로 다릅니다** (분리규칙 §3-5).

### 확인 과정에서 바로잡은 것

기억에 남아 있던 옛 방식들이 지금은 **오류(400)를 냅니다.** 안 쓰도록 확인했습니다.

| 옛 방식 | 지금 |
|---|---|
| `thinking: {type:"enabled", budget_tokens:N}` | `thinking: {type:"adaptive"}` |
| `output_format=...` | `output_config: {format: {...}}` |
| 답을 미리 채워 시작하기(prefill) | Opus 5 에서 **금지** — 400 |

시험이 이 셋을 매번 검사합니다. 되살아나면 실패합니다.

## 2. 대본을 세 겹으로 지킵니다

### ① JSON 모양은 **서버가 보장**합니다

구조화 출력(`output_config.format`)으로 스키마를 넘기면, 그 모양을 벗어난 답이
아예 오지 않습니다. 그래서 「형식이 깨져서 다시 만드는」 일은 없습니다.

### ② 규칙 검사 — 스키마로 표현할 수 없는 것들

글자 수·금지 표현·30초·클립 수는 JSON 스키마로 못 씁니다.
그래서 `app/core/script_rules.py` 가 따로 검사하고, **어기면 최대 2회 다시 만듭니다** (§6).

| 검사 | 근거 |
|---|---|
| 장면 4~6개 | §1 |
| 전체 30초 이하 | §8 |
| 장면 시간이 빈틈없이 이어짐 | §6 |
| 읽어줄 말이 그 시간 안에 읽히는가 (초당 6자) | §6 |
| 자막 1~2줄 · 한 줄 16자 | §7 |
| 영상 생성 장면 2개 이하 | §1-1 |
| 과장 표현 없음 (최고·1등·무조건·대박·역대급…) | §6 |
| 게시글 설명 맨 앞에 「유료광고 포함」 | §5 |
| 해시태그 5~12개 | §6 |

**다시 만들 때 무엇이 틀렸는지 알려줍니다.** 「그냥 다시」 가 아니라
「장면 1 이 3초에 45자입니다. 18자까지 됩니다」 라고 짚어서 보냅니다.

### ③ 광고 표시는 프로그램이 강제합니다

AI 가 빠뜨려도 프로그램이 붙입니다. **AI 도 담당자도 끌 수 없습니다.**
시험이 「AI 가 빠뜨린 경우」 를 일부러 만들어 확인합니다.

## 3. 담당자가 고친 대본도 같은 규칙으로 검사합니다

만들 때만 검사하고 사람이 고친 건 안 하면 구멍이 생깁니다.
그래서 검사기를 API 호출과 **분리해서** 만들었고, 화면이 같은 것을 씁니다.

담당자가 대본을 고치면 **그 자리에서** 위 규칙을 다시 봅니다.

- 어긴 게 있으면 화면 위에 한국어로 뜨고 **[영상 제작] 이 잠깁니다**
- 되돌리면 다시 풀립니다

> 화면 예: 「장면 1 · 읽어줄 말 — 3초에 37자는 너무 깁니다. 18자까지 됩니다. (19자를 줄여주세요.)」

## 4. 비용을 줄이려고 한 것

월 20편에 다시 만들기까지 하면 대본 호출이 적지 않습니다.

- **바뀌지 않는 부분에 캐시**를 겁니다. 규칙·말투·장면 공식이 여기 들어갑니다.
- **가게 정보는 캐시 뒤**에 둡니다. 시스템 프롬프트에 섞으면 매번 캐시가 깨집니다.
- 다시 만들 때 특히 값을 합니다 — 규칙은 그대로고 대화만 늘어나니까요.
- 실제로 쓴 토큰과 **캐시가 걸렸는지**를 돌려줍니다. 나중에 알면 늦습니다.

시험이 「가게 이름이 시스템 프롬프트에 섞이지 않았는지」 를 확인합니다.

## 5. 시험 115개 — 전부 통과

```
계약 (Stage 1)  22개
화면 (Stage 2)  26개   ← 대본 연결 시험 8개 추가
저장 (Stage 3)  37개
대본 (Stage 4)  30개
────────────────────
합계           115개
```

**실제 API 는 부르지 않았습니다.** 열쇠가 없고 이 작업 환경에서 막혀 있습니다.
대신 **가짜 client** 를 넣어 흐름 전체를 확인했습니다 — 규칙 검사, 다시 만들기,
광고 표시 강제, 오류 번역, 비용 계산, 화면 연결까지.

보내는 요청이 공식 문서대로인지도 시험이 매번 확인합니다.

```
model        : claude-opus-5
thinking     : {'type': 'adaptive'}
output_config: {"format": {"type": "json_schema", ...}}
system 캐시  : {'type': 'ephemeral'}
마지막 메시지 : user      ← assistant 면 Opus 5 에서 400
폐기 인자     : 없음
```

### 시험이 잡아낸 것

**옛 시험 두 개가 깨졌습니다.** Stage 2 때는 아무것도 안 넣고 버튼을 눌러도
다음 화면으로 갔는데, 이제 필수 칸을 채워야 넘어갑니다. 새 동작이 맞으므로
시험 쪽을 고쳤습니다.

**하단 문구가 낡아 있었습니다.** 「Stage 2 — 화면만 만든 상태입니다」 가
그대로 남아 있었습니다. 갈아끼울 수 있게 바꾸고, **낡은 문구가 남으면
실패하는 시험**을 넣었습니다.
