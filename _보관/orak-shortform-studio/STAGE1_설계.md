## 3. 왜 이렇게 설계했나 — 결정 10가지

지시서와 MVP 판정에서 **"빠뜨리면 큰일 나는 것"** 들을, 조심하는 대신
**타입이 강제하도록** 옮겼습니다. 사람의 주의력에 기대지 않는 것이 이번 설계의 방침입니다.

### 3-1. Kling 과 Ken Burns 가 같은 인터페이스를 씁니다

Kling 은 넣고 기다리는 방식이고 Ken Burns 는 그 자리에서 끝납니다. 성격이 아주 다릅니다.
그래도 **둘 다 `submit → poll → download`** 를 따르게 했습니다. Ken Burns 는 submit 시점에
이미 끝나 있고 poll 이 곧바로 "됐다"고 답합니다.

이렇게 하지 않으면 파이프라인이 두 갈래로 갈라지고, 재시도·복원·비용 기록을 **두 번씩**
만들어야 합니다. 두 벌이 되면 한쪽만 고치는 실수가 반드시 생깁니다.

### 3-2. 파이프라인은 벤더 오류 코드를 보지 않습니다

MVP 판정 21번(1303 백오프)과 22번(1200번대 재시도 금지)이 이 설계로 자동 충족됩니다.

각 Provider 가 자기 오류를 5가지 분류 중 하나로 **번역해서** 올립니다.

| 분류 | 뜻 | Kling 예 |
|---|---|---|
| `BACKOFF` | 자동 재시도 (지수 백오프) | 1302 · 1303 · 5000~5002 |
| `NEVER_PARAM` | **재시도 금지** — 보내도 같은 결과, 돈만 나감 | 1200~1203 |
| `NEVER_AUTH` | 재시도 금지 — 사람이 조치 | 1000~1004 · 1101 · 1102 · 1103 · 1304 |
| `NEVER_CONTENT` | 재시도 금지 — 대본을 고쳐야 함 | 1301 |
| `MANUAL` | 자동 재시도 다 쓰고 실패 → [다시 시도] 버튼 | |

`Retry.is_automatic` 이 참인 것은 **`BACKOFF` 하나뿐**입니다. 시험으로 못박아 두었습니다.
나중에 누가 1200번대를 재시도 목록에 넣으면 시험이 깨집니다.

### 3-3. 비밀값은 처음부터 안전합니다

`SecretStr` 은 `str()` · `repr()` · f-string · `print` · 로그 · 예외 메시지 어디에 넣어도
`★★★★` 만 나옵니다. 원문은 `reveal()` 을 **명시적으로** 불러야 나오고, 그 호출 지점은
검색으로 전부 셀 수 있습니다.

"조심해서 안 넣기" 가 아니라 "넣어도 안 새기" 입니다. MVP 판정 18번이 이 방식이라야 지켜집니다.
시험 3개가 11가지 출력 방법을 전부 확인합니다.

### 3-4. 광고 표시는 빼먹을 수 없습니다

자막을 만드는 함수가 `disclosure` 를 **키워드 필수 인자**로 받습니다.
빼고 부르면 그 자리에서 `TypeError` 가 납니다. 담당자가 끌 수 있는 스위치는 어디에도 없습니다.

법적 의무(표시광고법 · 공정위 추천보증 심사지침)라 "실수로 빠졌다" 가 성립하면 안 됩니다.

### 3-5. 참고 URL 은 열 방법이 아예 없습니다

`ReferenceUrl` 타입에는 `url` 과 `note` 두 칸뿐입니다.
`fetch` · `open` · `read` · `download` 같은 것이 **하나도 없습니다.**

§0-4가 금지한 자동 수집을 "안 만든다" 가 아니라 **"만들려면 타입부터 고쳐야 한다"** 로 바꿨습니다.
시험이 이 타입에 금지 기능이 생기지 않았는지 매번 확인합니다.

### 3-6. 30일 만료 대비를 빼먹을 수 없습니다

`VideoProvider` 계약에 `download()` 가 들어 있습니다. 이걸 안 만들면 계약을 만족하지 못합니다.
Kling 결과 URL 은 30일 뒤 삭제되므로 `succeeded` 를 받는 즉시 내려받아야 합니다 (MVP 판정 20번).

### 3-7. 껐다 켜도 이어집니다

`VideoJob` 은 **DB 에 넣었다 뺐을 때 되살아나야** 합니다.
프로그램을 다시 켜면 메모리에 아무것도 없으므로, 이 dataclass 의 값만으로 `poll()` 이 돌아야 합니다.

시험이 실제로 `asdict()` → `VideoJob(**값)` 왕복을 시켜 확인합니다 (MVP 판정 12번).
`external_task_id` 는 그래서 **필수**입니다.

### 3-8. "3초"와 "5초"를 섞을 수 없습니다

Scene 1 은 3초를 쓰지만 Kling 은 5초·10초만 만듭니다. 3초를 요청하면 1201 오류가 납니다.

그래서 값을 **두 개로 갈라 두었습니다.**

| 값 | 뜻 |
|---|---|
| `VideoRequest.request_sec` | Kling 에 요청하는 길이 (5 또는 10). **과금은 이 값 기준** |
| `Scene.use_sec` | 완성본에서 실제로 쓰는 길이 (3) |

이름이 다르니 실수로 바꿔 쓸 수 없습니다. 시험이 둘이 다른 값임을 확인합니다.

### 3-9. 분리규칙을 코드가 지킵니다

`Paths.assert_writable(path)` 를 거치지 않은 파일 쓰기는 만들지 않습니다.

- 허용: `내 문서\ORAK_SHORTFORM_STUDIO\` 아래
- 금지: **바탕화면 전체** · A 의 모든 폴더 · 동봉 자산 폴더 · 이미 있는 프로젝트 폴더

와일드카드로 폴더를 찾지 않고 **전체 경로를 문자 그대로** 비교합니다 (분리규칙 §3-2).
`오락_당근_콘텐츠` 를 찾다가 `오락_당근_배포도구` 가 잡히는 일이 없게 하려는 것입니다.

### 3-10. 돈이 나가기 전에 문이 하나 있습니다

`CostGate.build_plan()` 이 [영상 제작] 버튼과 API 사이에 섭니다.
여기서 막히면 **API 를 한 번도 부르지 않은 상태**라 요금이 0원입니다.

검사: 총 길이 30초 이하 · Kling 클립 수 한도 이하 · 남은 월 한도 이내.
막힐 때는 `PlanRejected` 가 **무엇을 고치면 되는지**(`hints`)까지 들고 옵니다.
30초를 넘으면 자동으로 잘라내지 않고 어느 Scene 을 줄일지 보여줍니다 (§8).

## 4. 분리규칙 갱신으로 바뀐 것

갱신본(§2)이 B 의 마스터 이미지 규칙을 바꿨습니다. **설계를 고쳤습니다.**

| | 이전 | 갱신본 |
|---|---|---|
| 마스터 이미지 위치 | `Desktop\오락이 마스터 파일\` 을 읽음 | **저장소 `assets\master\` 에 두고 EXE 에 동봉** |
| 바탕화면 | 마스터 폴더만 읽기 허용 | **전체 접근 금지** |
| 완성된 프로그램 | 바탕화면을 읽음 | 동봉된 3장만 읽음 |

고친 곳: `app/__init__.py` · `app/contracts/ports.py`
(`master_image_dir()` → `bundled_assets_dir()` + `master_images()`)

동봉 방식이라 **PyInstaller 로 묶었을 때와 개발 중일 때 경로가 다릅니다.**
`bundled_assets_dir()` 이 그 차이를 흡수하므로 바깥 코드는 구분하지 않습니다.

### ⚠️ 마스터 이미지를 올리기 전에 저장소를 비공개로 바꿔주세요

지금 이 저장소는 **공개(public)** 입니다.
공개 상태에서 이미지를 한 번 올리면, 나중에 비공개로 바꿔도 **이미 받아간 사람에게서는 되돌릴 수 없습니다.**

그래서 안전장치를 걸어 두었습니다. `.gitignore` 에 마스터 이미지 차단 두 줄을 넣었고,
**실제로 가짜 png 를 만들어 차단되는지 확인했습니다.**

```
1. 저장소를 비공개로 바꾸기 (Settings → Danger Zone → Private)
2. assets/master/ 에 3장 넣기
3. .gitignore 에서 아래 두 줄 지우기
      orak-shortform-studio/assets/master/*.png
      orak-shortform-studio/assets/master/*.jpg
4. 올리기.ps1
```

3번을 하기 전에는 올려도 깃허브에 올라가지 않습니다.
자세한 순서는 `assets/master/여기에_넣어주세요.txt` 에 적어 두었습니다.
