## 고친 것

1. **영상 표시·서빙** — `mediaUrl` 이 표식 없는 경로는 `/api/media/abs?p=절대경로` 로 묻고,
   서버가 허용 폴더(output·assets·ROOT) 안인지 검사 후 서빙. `serveLocalFile` 은
   전달된 기준 폴더 각각을 기준으로 검사(설치형 출력 폴더 지원). `publicUrlFor` 는
   출력 폴더 기준 상대 경로 + 세그먼트 인코딩.
2. **공개 주소** — SNS·포털 호스트(instagram/facebook/youtube/tiktok/naver …)는
   저장 단계에서부터 거절. 발행 확인창에 **[공개 주소 실제 확인]** 줄 추가 —
   조립된 영상 주소로 진짜 Range GET 을 보내 video/mp4 가 오는지 본다.
   (웹페이지가 오면 ❌ 차단, 네트워크 불통이면 ⚠ 경고)
3. **음성 실패 허용** — 음성이 실패하면 무음 트랙(anullsrc)으로 계속 만들고,
   음성 단계는 "⚠ 음성 없이 계속 만듭니다 — 원인" 으로 표시. 다시 만들기의
   "음성 파일이 없습니다" 차단도 제거. `voice_notice` 를 품질 정보에 남김.
4. **제작-맛집 DB 연결** — 오늘의 릴스에 [📇 맛집 DB에서 불러오기] + 이름 입력 시
   비슷한 업체 제안("혹시 이 가게인가요?"). 고르면 `restaurantId` 로 제작되어
   조사 없이 저장된 정보(수기 입력 포함)를 그대로 쓴다.
5. 검수 화면의 [즉시/예약 발행] → 릴스 화면 `?publish=` 이동이 실제로 창을 연다
   (예전에는 이동만 하고 아무 일도 없었다).

## 하지 않은 것 (정직 보고)

- 요구된 12단계 상태 모델(draft…cancelled) 전면 개편은 하지 않았습니다.
  기존 한국어 상태(기획/제작중/검수/승인/예약/발행완료/실패)가 전 화면·DB 에
  퍼져 있어, 전면 교체는 동작하는 것을 더 크게 부술 위험이 있다고 판단했습니다.
  대신 "부러진 지점" 을 고쳤습니다.
- 포터블 ZIP 배포는 이 프로젝트에 원래 없습니다 (설치형 .exe + start.bat 방식).
- 실제 Instagram 게시는 여전히 사용자가 [게시하기] 를 눌러야 나갑니다.
