## C. 비밀값이 설치본에 들어가지 않는지 — 실제로 시험함

**조사 중 실제 유출 경로를 발견했습니다.**
`next build --output standalone` 결과에 아래가 **그대로 복사되고 있었습니다.**

```
.next/standalone/.env                    ← API 키 평문
.next/standalone/data/.secret            ← 암호화 열쇠
.next/standalone/data/orak-studio.db     ← 암호화된 API 키
```

이대로 설치 파일을 만들었다면 **API 키가 exe 안에 실려 배포되었을 것입니다.**

**막은 방법**: `scripts/prepare-desktop.mjs` 가 담을 것을 고르고, 담은 **뒤에 다시 검사**합니다.
`.env` / `.secret` / DB 존재 여부 + `sk-ant-` `sk-proj-` `AIza` 형태 문자열을 훑습니다.

**검사가 헛돌지 않는지도 시험했습니다:**

| 시험 | 결과 |
|---|---|
| 정상 상태로 실행 | `✅ 비밀값 검사 통과` (종료 코드 0) |
| 가짜 키가 든 파일을 일부러 넣고 실행 | `❌ 비밀값이 설치본에 들어갔습니다. 중단합니다.` (종료 코드 1) |

즉 **검사는 실제로 막습니다.** 통과 문구가 장식이 아닙니다.

## D. 남은 위험

1. **코드 서명 인증서 없음** — 설치 시 Windows 경고가 뜹니다. 서명된 것처럼 보고하지 않습니다.
2. **앱 아이콘은 임시** — `electron/icon.png` / `icon.ico` 를 최종 로고로 바꾸고
   `node scripts/make-icon.mjs` 를 다시 돌리면 됩니다.
3. **설치 파일은 회사 PC 에서 만들어야 합니다** — Windows 에서만 NSIS 빌드가 됩니다.
